Bitmap и фильтр Блума в Hash Match

Как параллельный Hash Match строит bitmap по ключам build-таблицы и как сканер второй таблицы отбрасывает строки без пары, ни разу не заглядывая в первую. Таблицы и поля — как в реальном плане 1С из методички (вопрос 45, подраздел «Bitmap»).

1. Пошаговый пример: build, probe-скан с bitmap, Hash Match

Build — _Reference19017 (5 строк), probe — _Reference10 (8 строк), условие T2._Fld19019 = T1._Fld7420. Для счёта в уме: бит = ключ mod 10, корзина хеш-таблицы = ключ mod 4.

2. Песочница: фильтр Блума с k хеш-функциями

Добавляйте ключи build-стороны и проверяйте ключи probe-стороны. Нулевой бит — ключа точно нет. Все биты взведены — «возможно есть»: так и появляются ложные срабатывания. Прогон 1000 случайных ключей сравнивает фактическую долю ложных срабатываний с формулой (1 − e−kn/m)k.

Упрощённая модель для обучения. Настоящие хеш-функции, размер bitmap и число функций в SQL Server не документированы; здесь вместо них остатки от деления (раздел 1) и простые строковые хеши (раздел 2). Принцип от этого не меняется: нулевой бит — пары точно нет, все единицы — пара возможна, окончательно проверяет Hash Match.
