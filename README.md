# Оптимизация запросов MS SQL Server: профайлер, план запроса, специфика 1С

Методичка для подготовки к аттестации «Умение оптимизации запросов. Профайлер, план запроса». Покрывает 83 опорных вопроса и дополнительные вопросы 1а (ROW_OVERFLOW и LOB) и 50а (ORDER BY и агрегация): от устройства страниц и B-деревьев до разбора медленного проведения документа 1С. К ответам приложены схемы, демонстрационные SQL-скрипты и настройка технологического журнала.

**Как пользоваться:**
- у каждого вопроса есть блок **«Кратко»** — ответ для аттестации в 2–4 предложения, ниже — подробности, примеры и таблицы;
- блоки **⚠️** отмечают места, где исходные материалы расходились или ошибались, и разбирают, как на самом деле;
- **★** — вопросы повышенного уровня;
- [шпаргалка](docs/10-cheatsheet.md) — все 83 ответа одной-двумя фразами для повторения.

Схемы в тексте нарисованы на [Mermaid](https://mermaid.js.org/) и отображаются GitHub напрямую. Картинки лежат в `images/`.

## Примечания к исходным материалам

Методичка собрана из ответов на опорные вопросы, полученных из нескольких источников. Там, где ответы противоречили друг другу или документации, выбрана правильная версия, а место отмечено блоком ⚠️:

1. **Поиск плана в кэше** идёт по хешу текста пакета **до** разбора. `query_hash` — отпечаток для анализа, а не ключ кэша ([вопрос 12](docs/02-query-pipeline.md#12-этап-привязки-algebrizer)).
2. **IF/ELSE внутри одной процедуры не лечит parameter sniffing**: ветки нужно выносить в отдельные процедуры ([вопрос 58](docs/06-params-cache.md#58-способы-борьбы-плюсы-и-минусы)).
3. `nvarchar`-столбец и `varchar`-литерал — **саргабельно** (приводится литерал). Плохо обратное сочетание ([вопрос 26](docs/03-optimizer.md#26-sargable-предикат)).
4. Лимит ключа НК-индекса — **1 700 байт / 32 столбца** (SQL Server 2016+), а не 900 / 16 ([вопрос 5](docs/01-storage.md#5-включённые-столбцы-include-и-ключевые-столбцы)).
5. Табличная переменная с 2014 года допускает inline-индексы, а не только PK/UNIQUE ([вопрос 38](docs/04-statistics.md#38-временные-таблицы-и-табличные-переменные)).
6. Условие в параметрах `СрезПоследних` и в ГДЕ **может давать разный результат** ([вопрос 70](docs/08-1c-specifics.md#70-параметры-виртуальных-таблиц--в-скобках-а-не-в-где)).
7. Правило «самый селективный столбец первым» — упрощение ([вопрос 10](docs/01-storage.md#10--порядок-столбцов-и-селективность-в-составном-индексе)). Точка перелома не равна фиксированным «1–5%» и зависит от числа страниц ([вопрос 42](docs/05-plans-operators.md#42-table-scan-clustered-index-scan-index-seek-всегда-ли-scan--плохо)).
8. Автоматическая замена большого `В (&Массив)` на временную таблицу платформой **не подтверждена**: проверяйте по ТЖ ([вопрос 74](docs/08-1c-specifics.md#74-или-в-условиях-и-соединениях-замена-на-объединить-все)).

Изменения в исходных скриптах:
- `03_plan_warnings_demo.sql` больше не удаляет базу в конце: она нужна скрипту 05;
- из `02_statistics_demo.sql` убран черновой хвост, он оформлен как блок 10;
- в `05_query_store_practice.sql` добавлены предупреждение о зависимости от 03 и финальный шаг с покрывающим индексом.

Ответы на вопросы 36–37, 55, 66, 77–78 и практические задания 79–83 написаны заново: в исходных материалах их не было или они были неполными.
